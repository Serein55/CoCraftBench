# MC-NPC-50：Minecraft NPC Agent 评测协议

版本：**v0.1 设计草案**。日期：2026-10-28。

目标：评估中文指令理解、资源获取、依赖规划、持续执行、状态记忆、约束遵守及机制知识。正式任务共 **50题，5档各10题**。本次只新增独立评测设计，没有修改 Agent、开启游戏或运行任务。

**交付边界：已有任务目录、条件、判据和部分精确建筑蓝图；尚无封存世界包、服务器判分器、运行器和实际成功率。难度与预算是待验证的设计假设。**

## 1. 什么算一个任务

每题是一个独立回合，不能把第1题得到的工具带到第2题。默认空背包、无装备、0级经验、满生命和饥饿值。题目明确给出的地图资源属于条件的一部分。

“采集10个原木并制作木斧木镐”不能检查最终背包仍有10个原木，因为原木会被消耗。MC-01检查的是**本回合累计自然采集至少10个橡木原木，以及真正制作并保留木斧和木镐**。

“制作铁套”在本套件中指铁头盔、铁胸甲、铁护腿、铁靴子四件，并且必须穿上。四件配方合计24个铁锭；工具、燃料、工作台不计入这24个。不能只背着四件装备就说完成，也不能捡到成品护甲冒充制作。

“获得草方块”指背包中的 `minecraft:grass_block`，不是 `dirt`、小麦种子、草丛，也不是把地表变绿。

## 2. 固定环境和每题启动流程

| 项目 | 主评测设定 |
|---|---|
| 版本 | Java Edition 1.21.6 原版；关闭实验性玩法和村民交易重平衡 |
| 游戏模式、难度 | 生存、普通；不得混用和平与普通的结果 |
| 起始状态 | 空背包、无装备、零经验、满血满饥饿；白天开始 |
| 死亡 | 第一次死亡即终止，记录死亡失败，不免费复活继续累积进度 |
| 地图 | 每题使用A/B/C三份独立、预先检查并封存的世界快照 |
| 环境随机性 | 固定出生地、资源区、初始实体、交易内容、天气与开始时间；保存快照和配置哈希 |
| 时间流逝 | 保持相同原版时间流逝和随机刻设置；不为某个模型单独加速种植、熔炼或刷怪 |
| 资源 | 保证预算范围内至少存在一条合法完成路径；不把缺少资源误判为 Agent 失败 |
| 管理员权限 | 只供评测端布置和检查；Agent不得调用赠予、传送、改游戏模式或改方块命令 |
| 工具 | 各比较系统共享动作能力和相同观测权限；模型可以有不同规划方法 |
| 外部知识 | 默认禁用开放互联网；如允许Wiki，另报“知识辅助赛道” |

正式评测前，人工或独立脚本必须在每份快照中验证一条可行路径。当前A/B/C只是待选实例名，**没有编造已验证的种子编号**。

开始每题时：恢复世界快照 → 清空上回合 Agent 状态 → 核验背包、经验、资源、实体和服务健康 → 发布公共场景说明及本题指令 → 开始计时。API等待时间也计入墙钟时间。MC-48是唯一有意保留同一回合持久文件并重启程序的任务。

允许不同任务拥有不同场景资源，但同一题、同一实例中各模型的条件必须一致。比如MC-18提供成熟麦田，MC-26提供一个鸡蛋；这些都写进题面，不能临时暗中给某个模型补资源。它们也不能被描述成“随机自然世界从零生存”。

## 3. 五档难度与暂定预算

| 等级 | 任务 | 暂定墙钟上限 | 暂定模型调用上限 | 主要变化 |
|---|---|---:|---:|---|
| L1 简单 | 01—10 | 10分钟 | 30 | 基础采集、配方、熔炼、放置、交付 |
| L2 较简单 | 11—20 | 20分钟 | 60 | 工具等级、铁制品、动物交互、短链补给 |
| L3 中等 | 21—30 | 35分钟 | 100 | 铁套、钻石门槛、多个目标、完整小屋 |
| L4 困难 | 31—40 | 60分钟 | 160 | 跨维度、酿造、铁路、受约束建筑 |
| L5 很难 | 41—50 | 90分钟 | 240 | 高级附魔、综合基地、重启恢复、需求变更、草方块 |

预算是初版试跑起点，**没有证明足以完成全部任务**。正式收集分数之前用人工和基线校准，之后冻结。等级描述预期依赖深度与机制跨度，不承诺每一题一定比前一题更难；完成数据后可在下一版本重新分档，不应中途为某个系统改分档。

一个API请求算一次模型调用，包括规划、执行决策、反思、记忆摘要和重规划。报告输入/输出token，不能只数动作命令。统一按预算上限或时间上限先到者终止。框架启动时列模型、加载资源等非Agent决策请求不计入，但要另记服务成本。

## 4. 地图前提与防止随机性主导

任务JSON的 `fixture_requirements` 是地图作者清单，不是现成地图包。准备时至少满足：

- 林区有足量可采自然橡树，普通题资源源头可达；MC-50需要额外大型林区。不得把玩家建筑里的木头计为自然采集。
- 石、煤、铁、钻石等资源以未采掘方块存在；数量包括目标配方、必要工具和合理损耗。高级题允许更远或更深，但必须预验可达。
- 砂岸、水源、熔岩池和矿区都有合法进出路线。不能把“矿石在区块数据里存在”误当成“Agent有可行路线”。
- 提供足量指定成年动物。繁殖题检查本回合由Agent喂食导致的出生事件，不能用初始幼崽凑数。剪羊毛题提供至少8只成年白羊，避免把羊毛掉落随机数或再生速度变成主难点。
- 麦田题初始成熟作物数固定；复种判据接受任意合法生长阶段，不能要求终止时仍恰好是第0阶段。
- 鸡蛋只在MC-26的公开补给箱中提供1个，以消除等待下蛋；不提供蛋糕、牛奶桶等其他目标材料。
- 下界题预验传送门目的地、要塞与资源区，不把“传送后直接掉入熔岩”作为随机考题。不要预给抗火或成品药水。
- 高级附魔题有可反复利用的合法经验来源，例如原版刷怪房。它提供可获得经验的机制，不直接赠予经验等级。
- 每个施工区、农田区和牛栏区有不同锚点，互不重叠。指定玩家建筑和所有保护区在回合前做快照。

为了不把评测变成找数千格外资源的耐心比赛，建议先制作**受控生存场景**；纯随机开放世界作为后续独立赛道。地图资源不能包含本题目标成品，除非题目明确声明为输入。

## 5. 三个关键锚点任务

### MC-01：原木、木斧、木镐

输入为空背包，附近有自然橡树。目标是累计采集10个橡木原木，制作木斧、木镐并保留。

检查采集来源和制作事件。采集10个之后消耗原木是合法的；不应误要求背包还剩10个。反过来，初始补给箱放10个原木也不能算本题的自然采集。

### MC-21：铁套

从空背包开始，预备木、石、铁矿、燃料路线，制造四件铁甲并穿戴到对应槽位。需要记录四件制作事件，最终检查装备槽。24个铁锭只是护甲本体成本，不代表整个任务只需要24铁。

部分进度可按四件成品与四个装备槽拆分，不以机器人说“穿好了”为依据。

### MC-50：草方块

官方关于草方块的介绍明确指出，精准采集工具可以获得完整草方块；普通挖掘不等价于取得该物品。[Minecraft：Grass](https://www.minecraft.net/ru-ru/article/block-week-grass)

**正式题默认不提供**草方块、附魔工具、附魔书、绿宝石、铁锭、铁砧或经验等级。它们必须在回合中获得。禁止管理员赠予和携带草方块的末影人路线，以免把罕见实体遭遇变成主要随机因素；这是公开的评测路线约束，不是声称原版只有一种获取方法。

地图准备一个固定可用交易场景：

| 对象 | 受控内容 |
|---|---|
| 制箭师 | 固定可用的木棍换绿宝石交易，例如32木棍换1绿宝石；初始库存足够至少12次，不先锁死交易 |
| 图书管理员 | 固定存在精准采集I附魔书交易，例如12绿宝石加1本普通书；工作站可达 |
| 自然资源 | 足量木材、铁矿、燃料、甘蔗、牛和草方块 |
| 经验来源 | 交易、冶炼、采矿或地图公开的合法经验来源 |

这些具体交易是**主办方布置并封存的条件**，不是保证任意原版世界都会出现的报价。实际交易槽、库存、价格、经验和工作站必须在1.21.6快照中预验；不能只修改文档就当作已经可用。不要同时开启实验性交易重平衡。

一条可行规划应覆盖：基础工具 → 获得交易资源 → 换取绿宝石 → 普通书与精准采集附魔书 → 铁砧、合适工具和经验 → 加上精准采集 → 正确采集草方块 → 检查背包。铁砧由3铁块和4铁锭组成，即31个铁锭，还需要另外准备工具的材料。[Minecraft：Anvil](https://www.minecraft.net/nb-no/article/taking-inventory--anvil)

若Agent选择其他公开允许的精准采集路线，也应认可，不强制复现上述参考步骤。MC-50的部分分按阶段能力给分，不能因为没有使用铁砧路线就把合法附魔台路线判错。

正式成功要求：最终背包至少1个 `grass_block`，并有本回合使用带精准采集的合法工具打掉草方块、收取对应掉落物的事件证据。最终截图、自然草地或物品名称的口头描述均不能替代。

**配对诊断，不计入正式50题总分：**

1. 提供一把精准采集I铁锹，其他不变。若仍失败，多半卡在工具选择、方块识别或执行接口，而不是长程资源规划。
2. 只提供精准采集I附魔书。若这时成功而正式题失败，可以进一步定位交易或前置资源链。

主任务、工具给定版和书给定版必须分别报告，不能把简单版本的成功算进主榜。

## 6. 建筑验收：不是看起来像房子就算

`blueprints.json` 定义了相对坐标。地图作者为每题设置锚点，并给Agent相同的公开尺寸图；不能用隐藏的精确蓝图惩罚一个只收到“小房子”模糊指令的Agent。

基础木屋规范：5×5外轮廓，地板y=0，墙y=1到3，屋顶y=4。南侧中间一扇双格高橡木门；四个固定单格玻璃窗。内部要求空气，家具版才允许对应家具格。基本外壳需要92个橡木木板方块、4块玻璃、1扇门；**这不包含工作台、门配方的批量产出、家具、工具和施工损耗**。

家具版增加白床两格、工作台、熔炉、箱子；门到中央保留两格高通路。MC-49最终屋顶为圆石，其余墙面、门窗、地板和家具保持原规范。

完整检查包括方块类型、列出的关键朝向/状态、空气格、通路和保护区。未列出的装饰性状态不应计错。所有方块种类应从服务器读取，不用LLM或截图印象判分。

桥梁、农田和牛栏也提供蓝图。桥下水域不能被填平；牛栏最终有两头指定成年牛、门关闭、地板完整且无逃逸缺口。复种只检查作物存在并处于合法生长阶段。

## 7. 中断恢复和需求变更

MC-48、MC-49都在25块正确地板及至少5块正确墙体完成时触发一次干预；按服务器事件触发，不能根据不同模型的思考速度随意选择时间。

- MC-48关闭Agent程序10秒再启动，保留世界、背包和本回合持久文件，清空进程内存及内存对话。所有系统均有相同磁盘持久化权限。需要继续完成房屋，重启后新增至少10个正确方块，已完成地板不被拆除。
- MC-49由评测端发送固定中文修改：“屋顶改用圆石，保留其余结构和家具。”最终按修订蓝图验收；此条消息属于公开任务输入，不是测试人员临时救场。

如果因Agent一直不施工而未触发干预，该任务仍失败；不能把“没有发生重启”当作中断恢复成功。

## 8. 评分与报告

### 主指标

设s(t,k)为第t题第k份世界实例的严格成功，取值0或1。先对每题的实例取平均，再对50题取平均，避免因某题多跑几次而权重变大：

`Strict-SR = (1/50) × Σ_t [(1/K_t) × Σ_k s(t,k)]`

严格成功 = 所有任务判据满足，且未发生玩家伤害、保护区破坏或作弊行为。另报只看任务目标的 `Goal-SR`，以区分“任务完成但违反约束”和“任务根本没完成”。

分别报告L1到L5成功率，不用一个总分掩盖高级任务全失败。过程部分分只作诊断，不把采完木头但没建房等同于成功。

### 诊断指标

| 指标 | 明确口径 |
|---|---|
| 部分进度 | 一般题各终态谓词等权，数量条件按完成比例截断到1；MC-50采用JSON中的五个加权阶段 |
| 建筑正确率 | 所有要求方块和空气格的匹配比例；另报要求格之外的多余方块数、破坏保护区数 |
| 效率 | 成功回合耗时中位数、全部回合耗时分布、模型调用、输入/输出token |
| 重复失败 | 相同动作/目标与相同失败原因连续出现的次数；不能仅凭文字相似断言无进展 |
| 规划保持 | 问“你在做什么”或发生恢复后，是否仍执行同一目标；可在独立诊断版测试 |
| 玩家攻击 | 攻击意图/被拦截尝试与实际造成伤害分开记录 |
| 技术输出泄露 | 玩家可见消息中含已注册内部命令的消息数/非空消息总数；日志不计入 |
| 恢复与变更 | MC-48、MC-49单独报告最终成功、恢复耗时、错误拆除量 |

技术输出泄露属于NPC交互质量，单列报告，避免把“房子建好了但输出命令”和“没建成房子”混为同一种失败；实际游戏约束违规仍影响严格成功。

### 失败分类

每个失败至少标一个主因和可选次因：`language_understanding`、`planning`、`premature_stop`、`memory_loss`、`wrong_recipe_or_mechanic`、`wrong_tool`、`navigation`、`execution_api`、`tool_gap`、`constraint_violation`、`resource_budget`、`death`。

**工具缺失仍计入系统端到端失败，但必须标注tool_gap。** 例如Agent没有铁砧或附魔台接口时，MC-50失败不能全归因为模型不会规划。不能事后把所有做不出的题从分母中删除。

封存地图不符合前提、目标资源被评测程序破坏、确定的服务故障属于无效回合，记录原因并重跑；不能把“模型因为不断循环而触发限流”伪装成无效回合。

## 9. NLP课程的对照实验

建议比较：A原版Agent；B只改提示词；C增加可持久化的任务计划与阶段验收；D在C基础上增加失败恢复。四组共享相同动作工具、蓝图施工能力和模型预算。若只给C/D增加建筑工具，提升无法单独归因于规划，需要另做工具增强消融。

每题至少准备直接指令、口语表达、约束表达三种语义等价问法。保持物品、数量、地点、建筑尺寸与限制完全一致，不能把“穿上铁套”改写成仅“做铁甲”。改写文本在正式测试前冻结；每份实例分配一种表达，各模型看到相同表达。

训练/调试使用单独的教程地图和示例任务；不要把正式50题的完整参考步骤写进提示词，再宣称是新任务泛化。任务与部分配方的共享本来就存在，因此本套件主要支持受控端到端比较；若要声称未见组合泛化，需要另外预注册任务家族划分和污染检查。

## 10. 实施交付和静态检查

目前文件：`任务清单.md`、`tasks-50.json`、`blueprints.json`、`validation.json`。JSON是建议的判分DSL，**不能直接当作Mindcraft原生任务文件运行**。现有单目标物品检测不足以覆盖装备槽、附魔、药水、实体出生、建筑和中断事件。

已完成静态检查：总题数50、每档10题、ID唯一；目标物品和方块ID存在于本机1.21.6数据；引用蓝图存在；铁甲配方总计24铁；木屋外壳方块数量一致；草方块阶段权重和为1。

待完成：构建并封存150份实例、实现服务器事件记录与谓词、检查每题可行路径、校准时间/API预算、进行完整Agent评测。**静态检查通过不代表游戏任务已经跑通。**
